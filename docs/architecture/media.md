# Media and the showcase site (Task 17)

Every picture of the C64 in the documentation and on the site is a real
capture of `build/pl0.prg` running in VICE (`x64sc` 3.7.1, stock ROMs,
VICE's default palette), never a mock-up. There is no emulator on the
site: the program calls the BASIC ROM's floating-point routines, the only
open ROM set does not implement most of them, and the original ROMs cannot
be redistributed with clear rights; so the site shows recordings and
tells visitors how to run the program in their own emulator.

## The files

All in `docs/img/c64/`, committed (they are documentation), regenerated by
`make media`:

| File | What it shows |
|---|---|
| `demo.gif` | the first minute: title card, the editor with the starter, F1 draws the square, an edit (`i < 3`, `turn(120)`), F1 draws the triangle, F3 (discard? Y), the picker, KOCH, F1 draws the snowflake |
| `editor.png` | the editor at start-up with the starter program (SQUARE) |
| `editor-error.png` | a compile error: `forward` misspelled on line 15, `ERROR line 15: undeclared name`, the cursor on that line |
| `picker.png` | F3: `OPEN PROGRAM`, the 15 examples from INDEX, KOCH selected |
| `help.png` | F7: the help page |
| `save.png` | F5: `SAVE AS: MYSQUARE` |
| `square.png` ... `tree.png` | the 15 examples (names as in `examples/`), each at the end of its run: drawings show the bitmap screen, text examples their output with `-- PRESS ANY KEY --` |

Format: PNG with a palette (the colours of the capture, exact), 768x544:
VICE's 384x272 screenshot (320x200 and the visible border) scaled 2x with
nearest neighbour, so that the pixels stay sharp where browsers or GitHub
scale images. The GIF has the same size, one 16-colour palette.

Sizes (2026-11-15): the 20 PNGs 31 KB together (300 bytes to 3 KB each);
`demo.gif` 214 KB (264 frames, 30 s, 768x544). Total 245 KB; the built
site with the downloads is 0.46 MB.

## How they are made (`make media`)

`make media` runs `tools/media_stills.py` (the PNGs, about 2.5 minutes)
and `tools/media_demo.py` (the GIF, about 1 minute). `make media MEDIA="koch
help"` redoes only those stills, `make media MEDIA=demo` only the GIF.
Needs VICE with the ROMs (as `make smoke`) and Pillow (Python 3).

Common to both: a fresh headless `x64sc` per capture (`-console`, warp:
warp changes the wall time, never the emulated time), `build/pl0.prg`
injected into RAM (`-autostartprgmode 1`, as the test harness does: the
real autostart from the disk, about 80 s of emulated time, would only
add waiting), and a
copy of `build/pl0.d64` in drive 8, a 1541 with true drive emulation, as
in `tests/c64_app_examples.sh`. Keys go in through the monitor's `keybuf`.
Images come from the monitor command `screenshot "FILE" 2` (PNG of the
whole emulated screen with the border; it works headless). Chosen over
rendering dumped screen RAM with the character ROM because it is VICE's
own rendering, colours and border included, with no code of ours that
could get it wrong. `tools/c64img.py` checks every capture (384x272, the
border one colour, not blank) and converts it.

Stills (`tools/media_stills.py`): each capture is a `tests/vice_run.sh`
run with `--on TRIGGER 'keybuf ...'` steps (a trigger is a whole screen
line, as in the tests), then `pause` (the emulation runs on until the
harness's next screen poll, many frames in warp, so the frame on screen
is complete) and the screenshot. Examples: F3, CRSR down to the example's
INDEX entry, RETURN, F1, the end-of-run prompt (for a drawing it is on
the hidden text screen while the bitmap shows).

Demo (`tools/media_demo.py`): one VICE run plays a storyboard (wait for a
screen line, hold N seconds of C64 time, type keys one per frame). Frames
are taken at emulated-time checkpoints: a breakpoint on the KERNAL IRQ
entry `$FF48` with `ignore 1 5` stops the CPU at every 6th jiffy
interrupt (0.1 s of C64 time), then a breakpoint `exec 0000 ffff if RL ==
$00` (enabled for this step only) waits for raster line 0, so the
previous video frame is complete; there the stopwatch (`sw`) is read and
the screenshot taken. A frame's duration in the GIF is its measured
stopwatch interval, so interrupts that the program masks while it plots
do not distort the timing. Parts of the story are played faster: the
cursor moves 2x, the disk waits 4x and the Koch run (26 s on the C64)
5x; the page's caption says so. Identical consecutive frames are merged; a frame whose border
has two colours (the program switched between the text and the bitmap
screen while VICE drew it: real, but 20 ms on the C64 and 100 ms in the
GIF) is dropped. The title card is a C64 text screen drawn with the
character ROM of the VICE installation at generation time (nothing of
the ROM is in the repository). `--assemble` rebuilds the GIF from the
frames of the last run (`build/media/demo/`, also `gifNNN.png`, the
frames as they are in the GIF, for review).

## The site (`web/`, `make web`)

- `web/index.html` and `web/style.css`: one static page, no scripts, no
  external fonts or stylesheets; light and dark from the system setting.
  Sections: pitch, the demo GIF, the 15 examples (capture, name,
  description from INDEX, source in a `<details>` block whose `<pre>` has
  `tabindex="0"` so it scrolls from the keyboard), the editor's
  screens, run it yourself (downloads, the VICE commands, the keys), why
  there is no emulator in the browser, documentation links, licences.
- The gallery is generated (`tools/mksite.py --write`, between
  `<!-- gallery:begin -->` and `<!-- gallery:end -->`) from
  `examples/*.pl0` and INDEX; `make test` fails if it is stale
  (`--check`).
- `REPO_URL`: the repository address is in one place, `<meta
  name="repo-url">` in the page head (a placeholder,
  `https://github.com/OWNER/REPO`, until the repository exists). Links
  marked `data-repo-path` (the user guide `docs/USER-GUIDE.md`, the
  language reference `docs/LANGUAGE.md`, the README) are written from it.
  `make web REPO_URL=... REPO_BRANCH=...` sets the real one in the built
  copy; the Pages workflow passes `github.server_url/github.repository`
  and the default branch.
- `make web` (after `make dist`) builds `build/site/`: the page, the
  stylesheet, `img/` (the media), `dl/pl0.prg` and `dl/pl0.d64`,
  `LICENSE.txt`; then `tools/check_site.py build/site` checks it and
  prints the size of each file and the total:
  - every local `src`/`href`, `url()` in the stylesheet, `<style>` blocks
    and `style=` attributes exists and is what its extension says;
    `#fragments` exist; a link starting with `/` fails (the site lives
    under `/<repo>/` on Pages);
  - no external resources (only `<a>` may leave the site), no scripts,
    no `srcset` or `<source>`; every image has alt text and a size;
  - the page references the demo GIF, a capture for every INDEX entry,
    the five UI screens, both downloads and `LICENSE.txt`, and has at
    least one `data-repo-path` link (an empty page fails), each naming a
    file that exists in the repository;
  - size caps (constants at the top of the checker): each GIF at most
    2.5 MB, each PNG 300 KB, each HTML/CSS/text file 200 KB, all PNG and
    GIF files together 6 MB, the whole page 8 MiB;
  - a WARNING when the placeholder `https://github.com/OWNER/REPO` is
    still in the page (`make web` without `REPO_URL`).
  `make test` runs the same checker on the committed sources
  (`--source`: `img/` read from `docs/img/c64/`, `LICENSE.txt` from
  `LICENSE`, `dl/` checked by name against the two files `make web`
  copies) and `tools/test_check_site.py`, which builds a good site in a
  temporary directory and checks that it passes and that 17 broken
  variants fail (empty page, missing gallery image or download
  reference, a download typo, broken `#fragment`, missing file, external
  stylesheet, leading `/`, oversize GIF and PNG, script, srcset,
  external or missing `url()`, no repository link, a repository link to
  a document that does not exist).
- `.github/workflows/pages.yml`: on a push to the default branch, installs
  cc65 and VICE (for `c1541`; no ROMs), runs `actions/configure-pages`,
  `make dist web` with `REPO_URL`/`REPO_BRANCH` from the environment
  (never interpolated into the script), fails if the placeholder URL is
  still in the built page, and deploys `build/site` with
  `actions/upload-pages-artifact` and `actions/deploy-pages`. The media
  are not regenerated there. One manual step, once, in the repository:
  Settings > Pages > Source: GitHub Actions (the workflow's token
  cannot enable Pages itself).

## Licensing

`LICENSE` (MIT) covers the code, the examples and the site. No ROM images
or emulator files are in the repository or on the site; the captures are
VICE's rendering of this program and show the C64 character set and
colours from the emulator's ROMs.

## Known looks

- The GIF keeps the C64's own transitions, each for one 0.1 s frame: the
  cleared text screen while a program compiles, the picker drawn over
  the editor while `READING DISK...` shows, and the editor redrawing
  after a run (for one frame row 0 still shows the run's end prompt).
  They are what the C64 shows; only frames torn between the text and the
  bitmap screen are dropped.
- The README and the user guide embed the images by these paths; they
  are 768x544, so `width="384"` or `width="768"` keeps them sharp.

## Host renderings

`docs/img/host/` holds the host driver's renderings of the 10 drawings
(640x400, black on white), used in [overview.md](overview.md) to compare
with the C64. They come from `build/pl0host --pbm NAME.pbm
examples/NAME.pl0` and `python3 tools/pbm2png.py NAME.pbm NAME.png 2`
(regenerated byte for byte on 2026-11-15); they are not made by
`make media`.
