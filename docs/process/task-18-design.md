# Task 18 expanded design: documentation and the development trail

Audience and success (spec section 1): a colleague opens the GitHub repository and finds professional documentation; reads the README and understands how Superpowers was used; can run the software in VICE in minutes. This task writes the words. Accuracy is non-negotiable: every claim must be checked against the code, the tests or a real run; no invented numbers.

## Deliverables

1. `README.md` (the front door; ~1-2 screens before scrolling matters): one-sentence pitch; the demo GIF (docs/img/c64/demo.gif) and 3-4 screenshots (editor, Koch, tree, an error); "Try it in 2 minutes" (install VICE, download build/dist or the Pages download links, `x64sc -autostart pl0.d64`; the key strip: F1 run, F2 new, F3 open, F5 save, F7 help, RUN/STOP = Esc); a short example of the language (a real program from examples/ with its picture); the examples table (name, one line, thumbnail from docs/img/c64); a "What makes this interesting" section (floats via the BASIC ROM, procedures with parameters, turtle graphics, a real editor in 40 columns, everything fits in a 64K machine: give the real numbers from the memory map); an honest "Limits and known issues" section (no browser emulator and why, 38 KB total, 8 KB source, 768 instructions, drawing time up to ~26 s for Koch, loading an 8 KB file takes ~40 s on a real 1541, RUN/STOP+RESTORE loses the text, ...: take them from the reports/ledger); a "How this was built with Superpowers" section (short: 6-10 lines + a link to docs/HOW-THIS-WAS-BUILT.md); links to every document; build/test commands (`make test`, `make check`, `make check-full`, `make media`, `make web`); licence line; badges are not needed (no remote yet).
2. `docs/USER-GUIDE.md`: install and start (VICE, ROMs note, real hardware/other emulators note), the screen anatomy (annotated with the editor screenshot), editing keys table (exact, from docs/architecture/editor.md and the code: verify), running a program (F1; text vs drawing; SPACE toggles; any key returns; RUN/STOP stops), errors (what they look like, the cursor jumps to the line), saving and loading (names, the disk, replace, the picker, what is on the disk: PL0, INDEX, examples; how to get your programs out of a d64 with c1541 and into a PC), the 15 examples one by one (one paragraph, the picture, the source in a collapsible block or fenced block, what to try changing), a short "writing your first program" tutorial in 5 steps (variables, loop, procedure with a parameter, a drawing, math), troubleshooting (nothing happens after F1? slow drawing? disk error messages and what they mean; key mappings in VICE/Esc; warp mode to speed up), and tips (case-insensitive, comments in braces, 38-character lines).
3. `docs/LANGUAGE.md`: the complete language reference: overview; lexical rules (case-insensitive, identifiers up to 16 chars, numbers, strings up to 16 chars, comments `{ }`, no exponent literals); EBNF grammar (derive from src/core/compiler.c and the tests: verify every production against the compiler); each statement (assignment, call, begin..end, if..then, while..do, `!` output including string and bare `!` newline, `?` input, turtle statements); expressions and operators with precedence and unary minus; conditions (`odd`, relational; `#` and `<>`); constants and variables; procedures: parameters by value, nesting up to 4 levels, recursion, scope rules, parentheses optional with no parameters but `()` is rejected; built-in functions (sin cos atan sqrt abs int exp log: radians, int = floor, domain errors); turtle graphics (coordinates, angles clockwise, start state, clipping, pen); number formatting rules (exact, from num_host.c/the tests); limits table (MAX_* values from src/core/limits.h, nesting 16, recursion depth about 60 with the actual measured numbers, source 8192, etc.); runtime error line semantics (operator's line); and the COMPLETE list of error messages with an explanation and an example for each (every message from src/core/errors.c must appear verbatim: tools/check_error_docs.py enforces it and is now active because this file exists: make sure `make test` passes with it). Add a "differences from Wirth's PL/0" section (floats, parameters, comments, strings, turtle, math functions, `?`/`!` semantics) with a short history note about Niklaus Wirth's PL/0 (from *Algorithms + Data Structures = Programs*, 1976; keep it accurate and modest).
4. `docs/architecture/overview.md` (the engineering story for colleagues): the layer diagram (mermaid, GitHub renders it): editor/UI, compiler, VM, platform layers (num/gfx/io) with host and C64 implementations, the test layers; the P-code table (from pcode.h: opcodes and meaning); the VM frame layout; the memory map diagram (mermaid or ASCII from docs/architecture/memory-map.md: regions, sizes, who lives where, the $A000 source buffer, HIBSS, LOWBSS, bitmap at $E000, matrix $CC00); the key engineering decisions with the reason each (ROM floats vs own library; exact bignum number formatting because ROM FOUT/FIN are wrong in the 9th digit: with the evidence; ASCII internal encoding and the charmap wrapper; gap buffer; clipping shared between host and C64; the cc65 -O miscompile findings with the reproducers in tests/c64/; the memory squeeze and how it was solved; true-drive disk tests); the numbers (sizes per module, free bytes, per-example run times); how host and target tests relate; how to add an example (the rules and the checks). Link to the existing detailed documents (spike-results.md, memory-map.md, testing.md, editor.md, media.md, examples-budget.md) and make sure they are consistent with the final state (fix stale statements you find; list what you fixed).
