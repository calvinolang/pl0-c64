# Task 16 expanded design: build products, acceptance gates, CI

Most pieces exist already (make c64 -> build/pl0.prg; make disk -> build/pl0.d64; c64-num/gfx/io/core/editor/disk/app/mem/examples targets; tools/c64_mem.py). Task 16 turns them into a reproducible, documented acceptance gate and adds the last missing end-to-end proofs.

## Deliverables

1. `make check` — the standard gate: host `make test` (unit tests + examples) AND the on-target smoke suite `make smoke` (= c64-num, c64-gfx, c64-io, c64-core, c64-editor, c64-disk, c64-app which includes c64-mem). If VICE (`x64sc`, `c1541`) is missing, `make smoke` prints how to install it (apt package name) and exits NONZERO unless `ALLOW_NO_VICE=1` is set (then it prints "SKIPPED: VICE not installed" and exits 0). `make check-full` = `make check` plus `make c64-examples` (all 15 examples through core_check) plus the new app-level example run below. Print a summary table at the end of `make smoke` (case name, pass/fail, seconds).
2. `make dist` — copies the final products to `build/dist/`: `pl0.prg`, `pl0.d64` (with a README line? no: just the files) and prints sizes; the d64 must contain `PL0` (PRG), `INDEX` and the 15 examples (verify by reading the directory with c1541 and comparing every example file byte for byte with examples/*.pl0 — `tools/mkdisk.py --verify` exists: reuse).
3. Autostart acceptance (`make c64-autostart`, part of smoke): start VICE headless exactly as a user would (`x64sc -autostart build/pl0.d64` with the default KERNAL ROMs and true drive emulation on; also `-autostart build/pl0.prg` separately) and prove the editor boots by screen text (status bar `PL/0   SQUARE`, the bottom key bar line exact) within a bounded number of emulated cycles; then press F1 and check the drawing appears (bitmap pixel count against the host render of the SQUARE starter). This is the exact first-minute experience a colleague gets in the web demo.
4. App-level example run (`make c64-app-examples`, part of check-full, NOT of smoke because it is slow): for each of the 15 examples, in a fresh VICE with the d64 attached: F3, move the selection to the example (cursor down N times from the list order printed by `tools/mkdisk.py --index`, or by typing nothing else), RETURN, F1, wait for the end-of-run prompt, then check: text examples -> the program output lines on the screen (use the tolerant comparison against examples/NAME.expected; for outputs longer than the screen compare the visible tail and say so), drawings -> the bitmap against the host render with the overlap check of tools/check_c64_run.py; also record elapsed emulated time per example through the final app (cycles from VICE) and write a table to docs/architecture/examples-budget.md (column `C64 app run (s)`), failing the target if any example needs more than 30 s of run time. It is the final acceptance of the product. Use a per-case timeout; run cases sequentially; print progress.
5. Clean-clone proof: from a fresh `git clone` of the repository (the branch HEAD, into a new temporary directory under the scratchpad <scratch directory>) run `make check` and record the result and timing in docs/architecture/testing.md (README quick start will point to it). Anything that only works in the worktree (untracked files, absolute paths, tools not in the repository) must be fixed. Also run `make clean && make check` in the worktree once.
6. CI: update .github/workflows/ci.yml: job `host` (make test) as now; job `target` that installs `cc65 vice` (and a virtual display only if x64sc needs one: prefer `-console`/headless options already used by the harness; document what you verified locally; the job must not rely on a display) and runs `make smoke`; both jobs cache nothing fancy. If you cannot verify the target job locally beyond using the same Makefile target, say so in the report. Do not push anything or create a GitHub repository: the workflow file is only committed locally.
7. Docs: docs/architecture/testing.md becomes the single place describing the test layers (host unit tests, host example goldens, on-target num/gfx/io/core/editor/disk/app, autostart, app-level examples, memory gate), how to run each, what `make check` and `make check-full` cover and their typical durations (measure them), how to install VICE and cc65 (Ubuntu), the VICE keyboard mapping notes (Esc = RUN/STOP). Keep it accurate and short.
8. Carry-over items to fix here (small): docs/architecture/memory-map.md RODATA/DATA/INIT range row is inconsistent with the current CODE end ($7464) and BSS start ($7E37): regenerate the module table from the current map (tools/c64_mem.py may already print it: make the doc generated or checked by a test so it cannot drift: `make c64-mem` should fail if the doc's headline numbers differ from the map); Task 14/15 minor doc items: docs/architecture/editor.md says an error always re-centres the view (the code re-centres only when the line is out of view: fix the wording); the Makefile c64-editor comment says about 1 minute but the suite takes about 2.5 minutes: fix.

## Constraints
No new product features; no change of the language, the editor behaviour or memory layout (BSS end must stay <= $97FF with >= ~100 bytes free: if any change to the product is unavoidable, report it). Pristine host `make test`. Every new Makefile target documented; every long target has a timeout and prints progress. No build artifacts committed.
