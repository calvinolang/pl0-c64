# Task 15 expanded design (controller's dispatch; refines and overrides the plan text where they differ)

Task 15 = run flow + example picker + disk save/load, on top of the Task 14 editor. Examples are loaded from the DISK, not embedded (plan amendment). The disk image is built in this task (`make disk`) because the picker needs it; Task 16 finalizes the build products and the VICE gate.

## STEP 0 (first, before any feature code): free low RAM
Only 243 bytes are free below $97FF (BSS ends $970C). Before adding code:
1. Move the VM stack (static array of MAX_STACK num_t = 2560 B) into HIBSS ($C000-$CBFF; the editor already uses 460 B there, ~52 B remain afterwards). HIBSS is never banked out by the fp_* shims; main() clears it.
2. Remove the ~950 B of textbuf code the C64 build does not use (ld65 cannot drop functions inside an object: use `#ifdef`/a define or move rarely used functions to a second object file) — keep host tests complete.
3. The static `Program` (4741 B) is idle outside compile+run: the picker and the disk layer REUSE that memory as scratch (a union / a shared scratch pointer with a documented ownership rule: scratch is valid only while no compile/run is in progress; assert/guard it).
Report the map numbers (BSS end, free bytes) after step 0 and at the end. Keep BSS end <= $97FF. If the remaining code does not fit even so: STOP and report BLOCKED with numbers and options.

## Run flow (F1)
- F1: `pl0_compile` the buffer text (tb_text); on a compile error return to the editor with the error (as now).
- On success: `io_text_open()` (clear text screen, home), `pl0_run`. Output via the io layer scrolls. The first turtle statement switches to the bitmap (gfx_open); the run continues there.
- RUN/STOP stops the program: `ERROR line N: stopped` (E_STOPPED).
- When the run ends:
  - runtime error: switch to the text view, print `ERROR line N: <message>` after the program's output, then `-- PRESS ANY KEY --`; on key return to the editor WITH the error shown and the cursor on that line.
  - normal end, no graphics used: print (on a new line) `-- PRESS ANY KEY --`, any key returns to the editor.
  - normal end with graphics used: stay on the drawing; SPACE toggles between the drawing and the text view; any other key returns to the editor. The text view ends with `-- SPACE: DRAWING  ANY KEY: EDITOR --`, and the drawing has no overlay. A first-time user must find this out from the help page (F7) and docs; update the help text in the editor accordingly (the text in the help page must tell: after a run, SPACE = switch drawing/text, any other key = back to the editor, RUN/STOP stops a running program).
- `gfx_close()` is called when returning to the editor; the editor does a full redraw on entry; the source text and editor state are untouched by a run (verify after every run: the buffer is identical).
- The text view must show the output printed so far when the user toggles during/after the run: the io layer's text screen is untouched while the bitmap is shown (VIC bank 3, text RAM in bank 0).

## Disk layer (device 8; use the current device number from $BA when the program was started, default 8)
- Files are SEQ files with the program text as RAW ASCII bytes ('\n' = $0A line ends), so a PC can read them with `c1541 -read` and the tool `tools/mkdisk.py` can write them with `c1541 -write name,s`. File names: uppercase letters, digits and `-` `_` `.`, 1..12 characters (the editor's `NAME` field; no extension on disk: `FACTORIAL`, not `FACTORIAL.PL0`; document it).
- Use the KERNAL file API (SETNAM/SETLFS/OPEN/CHKIN/CHRIN/CHKOUT/CHROUT/CLOSE/READST; directly from C through cc65's `cbm.h` functions or small assembly: but NOT cc65 stdio; remember the ASCII charmap: file names passed to the KERNAL must be PETSCII: uppercase ASCII letters $41-$5A are the same bytes on disk so the conversion is the identity for the allowed character set; verify on the real emulator with a directory listing).
- Save: prompt on row 24 `SAVE AS: NAME_` with the current name prefilled and editable (DEL, letters, digits, `-_.`; RETURN confirms; RUN/STOP cancels); validate (non-empty, allowed characters, <= 12) with plain messages (`BAD NAME`); if the file exists (check the directory) ask `REPLACE? (Y/N)`; replace by saving to `@0:NAME,S,W` (or scratch then save: choose what works with the 1541 emulation and the virtual device) ; write the text with CHROUT in a loop (NOT KERNAL SAVE: SAVE writes PRG files with a load address and the source buffer is under the BASIC ROM at $A000: reading it byte by byte from C with the ROM banked out is fine). After the write read the drive error channel (15): on error show `DISK ERROR: <plain text>` mapping the common DOS codes to plain words (62 FILE NOT FOUND, 63 FILE EXISTS, 72 DISK FULL, 74 NO DISK / DRIVE NOT READY, anything else: `DISK ERROR nn`); on success show `SAVED NAME` and clear the modified flag, set the program name.
- Open (F3): if the text is modified ask `DISCARD PROGRAM? (Y/N)` first (as F2 does); then the picker. A load never destroys the current text unless it succeeds: first pass counts bytes by CHRIN without storing (if more than MAX_SOURCE-1 bytes: `FILE TOO BIG`, nothing changes), second pass loads into the buffer (invalid characters such as CR $0D are converted: CR -> '\n', LF -> '\n', CRLF -> one '\n'; tabs -> a single space; other bytes outside $20-$7E dropped); set the name, clear the modified flag, cursor at line 1 column 1.
- Picker (F3): a 40x25 list screen as in the approved mockup: row 0 reverse title ` OPEN PROGRAM `, rows 2.. entries `NAME` (12 chars) plus a description of up to 24 chars (taken from the first `{ description }` comment of the file; for examples from the INDEX file, below), the selected entry in reverse video, bottom bar ` RETURN open  RUN/STOP back  (cursor up/down)` (<=40 columns). Cursor up/down moves the selection, wrapping at the ends or stopping (choose and document), the list scrolls if there are more entries than rows (21 visible); RETURN opens; RUN/STOP returns to the editor unchanged. Order: the examples first (from the INDEX file, in file order), then the user's own saved programs (all other SEQ files in the directory, alphabetical, no description or the description read from their first line if cheap), never listing INDEX itself or non-SEQ files (like the `PL0` program file). An empty disk or no disk shows a plain message (`NO DISK` / `NO PROGRAMS`).
- INDEX file: a SEQ text file named `INDEX` built by `tools/mkdisk.py` from `examples/*.pl0`: one line per example `NAME<space>description` in a fixed order (simple first: SQUARE, POLYGON, SPIRAL, ... as you judge best for a demo: say the order in the report). The disk layer reads INDEX with CHRIN line by line; the picker keeps its entries in the scratch memory (the idle Program memory) or draws straight into screen RAM and re-reads names from there; choose the simplest robust design and document the ownership rules.
- `make disk` builds `build/pl0.d64` with c1541: the program `build/pl0.prg` as a PRG file named `PL0` (the autostart file), INDEX, and the 15 examples as SEQ files (uppercase names without extension) by `tools/mkdisk.py` (a small Python script; also able to verify the d64 afterwards by reading the files back with `c1541 -read` and comparing with the sources). The disk title: `PL0 TURTLE`. Document the target in docs/architecture/testing.md.

## Tests (on the real emulator, `make c64-editor`-style target `make c64-app`, plus keep c64-editor, c64-num/gfx/io/core and host `make test` green)
Extend tests/vice_smoke.sh (or add tests/vice_app.sh) with the d64 attached (`-8 build/pl0.d64`; headless VICE with a virtual device or true drive emulation: choose what is reliable and document; the test harness must be able to read the saved file back from the d64 afterwards, `c1541 -read`, to prove the bytes on disk):
1. run_factorial (open FACTORIAL via F3, move to it with cursor keys, RETURN; F1; the screen shows the output line with 3628800 (FACTORIAL prints 1..12 factorials) and `-- PRESS ANY KEY --`; a key returns to the editor with the text identical to the loaded example).
2. run_error: `!x.` F1 -> the editor shows `ERROR line 1: undeclared name` (compile error); a runtime error case `!1/0.` -> after F1 the text view shows `ERROR line 1: division by zero` then `-- PRESS ANY KEY --`, then the editor shows the same error with the cursor on line 1.
3. drawing_runs: open SQUARE, F1, check the bitmap against the host render (tools/check_c64_run.py overlap check as in the examples harness), SPACE toggles to the text view and back, any other key returns to the editor with the text intact.
4. stop_with_runstop: type `var i; begin i := 0; while 1 = 1 do i := i + 1 end.`, F1, inject RUN/STOP, expect the editor with `ERROR line 1: stopped` and the text intact.
5. save_roundtrip: type a program, F5, name TEST, RETURN -> `SAVED TEST`; read the file back from the d64 with c1541 and compare the bytes with the typed text; F2 new; F3 pick TEST (listed after the examples) -> the text is restored, name TEST, not modified.
6. save_bad_name (empty name, a name with `*` or `/` or 13 characters): plain `BAD NAME`, nothing written (verify the d64 directory unchanged), replace_confirm (save over an existing file: N keeps the old bytes, Y replaces them).
7. picker: navigation with up/down and the scrolling case (save >= 8 extra programs so the list exceeds 21 entries: verify the last entry is reachable and the first rows scrolled), RUN/STOP cancels with the text unchanged, discard confirm when modified, FILE TOO BIG (create a 9000-byte SEQ file on the d64 with the test tooling), a file with CRLF line ends loads as '\n' (create with the tooling).
8. no_disk: without a disk attached F3 shows `NO DISK` (or the plain equivalent) and F5 shows `DISK ERROR: NO DISK`; the editor stays usable.
9. source_at_a000: a save/load roundtrip of a near-full buffer (e.g. 8000 bytes) proves reading/writing the buffer under the BASIC ROM through the KERNAL I/O works (the carried-forward concern from the spike).
10. memory: assert (from the map file in the Makefile target) BSS end <= $97FF and print the free bytes.
Make cases independent (fresh VICE per case), each with a timeout; the suite must not hang. Show RED then GREEN with pasted screens for the key cases.
